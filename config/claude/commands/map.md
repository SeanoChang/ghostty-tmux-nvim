# Codebase Map

Generate a structured codebase index for quick agent orientation.

## Instructions

1. **Scan the project root** using Glob and Read tools. Identify:
   - Top-level directories and their purpose
   - Entry points (`main.*`, `index.*`, `app.*`, `server.*`, `cli.*`, `mod.rs`, `lib.rs`, `__init__.py`, `manage.py`, etc.)
   - Config files (`package.json`, `Cargo.toml`, `pyproject.toml`, `tsconfig.json`, `Makefile`, `docker-compose.*`, etc.)
   - Key source directories (`src/`, `lib/`, `app/`, `pages/`, `routes/`, `api/`, `components/`, `modules/`, etc.)

2. **For each source directory**, list files with a one-line summary of what the file exports or does. Group by directory. Go max 3 levels deep.

3. **Skip**: `.git/`, `node_modules/`, `target/`, `dist/`, `build/`, `.next/`, `__pycache__/`, `*.lock`, `.gitignore`, `.env*`, vendored/generated files, binary assets.

4. **Identify the dependency/module graph** by reading entry points and noting key imports.

5. **Write the output** to `.claude/codebase-map.md` in the project root using this format:

```markdown
# Codebase Map
> Auto-generated by /map — <date>

## Stack
- Language: ...
- Framework: ...
- Package manager: ...

## Directory Structure
<tree view with one-line descriptions>

## Entry Points
| File | Purpose |
|------|---------|
| ... | ... |

## Key Modules
### <directory>
| File | Exports / Responsibility |
|------|--------------------------|
| ... | ... |

## Dependency Graph (simplified)
entry → module_a → module_b
                 → module_c → shared_utils
```

6. Keep each file summary to **one line max**. The entire map should be scannable in under 30 seconds. Aim for conciseness over completeness.

7. If `.claude/codebase-map.md` already exists, **update it** rather than regenerating from scratch — preserve any manual annotations the user may have added (marked with `<!-- user -->` comments), and note what changed at the top.
